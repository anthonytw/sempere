# Design: Custom saved tools in the palette (Sempere 1.3, issue #11)

Status: design, 2026-11-18; reviewed 2026-11-18 (decisions at the end). Paths are relative to the repository root. Issue #11: "Let people save their own tools (ink type, exact width, color, opacity) as palette entries, and pick them as easily as
the built-in ones. The palette is Sempere's own on every device, with one tool model, so saved tools work the same on iPad, iPhone and Mac. Saved tools could sync through the vault's shared settings."
It leads 1.3 (`docs/design/1.2-plan.md`). No code changed.

## 1. Goal and non-goals

**Goal.** A user saves a pen setup ("Fine red pen": pen, red, 1.5, 100%) or a highlighter ("Yellow marker": marker, yellow, 14, 40%) as a palette entry and picks it with one tap, on iPad, iPhone and
Mac. The entries follow them across devices through the vault's shared settings, like the other settings.

**Non-goals.**
- Saving the eraser, the lasso, the ruler or the pixel eraser's width (the eraser has its own mode and size rows).
- Presets that change more than ink, color, width and opacity (no per-note paper, no "pen plus recognition on").
- PencilKit's own saved tools (`PKPaletteNamedDefaults`, settings-sync.md §5.3): Sempere's palette does not use PencilKit's picker (`PKToolPicker` never shows on a Mac).
- A new vault file or a `features` marker (D1).
- Sharing presets with other people through the app (the CLI can export and import a file, §3.6).

## 2. What exists today

- `DrawingToolState` (`Sources/Sempere/DrawingTools.swift`): pure, Linux-tested; `tool` and `previousTool`, `inks: [InkTool: InkSettings]` where `InkSettings` is `color` (opaque `Color`), `width`, `opacity`; swatches,
  `opacityPresets` (0.25, 0.5, 0.75, 1), `widthPresets(for:)`, `widthRange(for:)` (PencilKit's `validWidthRange` per ink; stored widths outside are clamped), `encoded()` / `init(decoding:)` for `UserDefaults`.
  Inks (`InkTool`): pen, monoline, fountainPen, marker, pencil, watercolor, crayon.
- `DrawingToolbox` (`Apps/Sempere/SempereApp/DrawingToolbox.swift`) owns the one shared state, maps it to `PKTool` and persists it in `UserDefaults`; change tools through it, never on a canvas.
- `DrawingPaletteView` (`Apps/Sempere/SempereApp/DrawingPaletteView.swift`): full bar (tools, swatches, widths, opacity), compact bar (pen, marker, eraser, lasso; always on iPhone; the Compact Palette setting `editor.compactPalette`), `swatch(_:index:ink:)`, `widthButtons`, `widthSlider`, `opacityMenu`, system color picker.
- Shared settings (`docs/settings-sync.md`, format.md §13): `settings.age`, flat dotted keys, per-slot last-writer-wins merge with `$meta`, opt-in per device and per vault ("Sync Settings with This Vault"),
  local overrides, type blocks, registry `Sources/Sempere/SharedSettingsCatalog.swift`, schema `docs/settings.schema.json`, snapshots of each version's registry, unknown keys kept verbatim by older readers (§6.2 rules 1 and 5).
- CLI `sempere settings list|get|set|reset|edit|validate|schema` (settings-sync.md §7).

## 3. Design

### 3.1 The preset (D2)

```json
"palette.tool.3f9c1a52-7e0b-4d9a-9a54-1d2c8b6e4f10": {
  "name": "Fine red pen",
  "ink": "pen",
  "color": "#D32F2F",
  "width": 1.5,
  "opacity": 1,
  "at": 1764727900000
}
```

| Field | Type | Rule |
| --- | --- | --- |
| `name` | string | 1 to 40 characters after trimming, NFC; not unique (two can share a name; the CLI then needs the id) |
| `ink` | string | one of `InkTool`'s raw values (`pen`, `monoline`, `fountainPen`, `marker`, `pencil`, `watercolor`, `crayon`); an ink this version does not know hides the preset and keeps it (a newer app may add inks). Parsed with `InkTool(rawValue:)`, **never** `InkTool`'s `Decodable`, which turns an unknown ink into `.pen` (format.md §5.6) |
| `color` | string | `#RRGGBB`, opaque (`InkSettings.color`; opacity is separate), as drawn on light paper (dark mode display mapping is the palette's existing `shown(_:)`) |
| `width` | number | within `DrawingToolState.widthRange(for: ink)`; out of range is **skipped** with a warning by the settings rules (§2.3 of settings-sync), not clamped, so two devices never differ; the editor only offers valid widths |
| `opacity` | number | 0.05 to 1 (`clampOpacity`) |
| `at` | integer | creation time in Unix ms; orders presets that `palette.toolOrder` does not list |

Width is in PencilKit tool units, not points, like every ink width in the palette (`widthPresets`), and `PKStrokePoint.size` is not the drawn width (CLAUDE.md gotcha): a preset stores what the palette's
width control stores, so a preset and the same manual choice draw the same.

### 3.2 Where it is stored (D1, D3): the shared settings, one slot per preset

- **Key family `palette.tool.<uuid>`** (lowercase UUID) with the object above as its value, plus **`palette.toolOrder`**: an array of ids, the user's order.
  One `palette.` prefix for both, like the catalog's other dotted keys (`eraser.mode`, `editor.compactPalette`).
- One slot per preset, not one array: slots merge per key (settings-sync.md §3), so two devices that each add a different preset both keep theirs; one array slot would lose one. Editing a preset is a write to its slot; the later write wins for that preset only.
- **Delete** is a reset of the slot (the `$meta` entry stays without a value: settings-sync.md §2.2), so a device that still holds the preset does not bring it back. Reset entries
  (about 80 bytes each) stay for good; the 64 cap counts live presets only, so a user who creates and deletes presets for years grows the file by kilobytes, which is accepted.
- **Order** is `palette.toolOrder`, one slot, last writer wins. Reconciliation on read: ids listed whose preset is missing are skipped; presets not listed are appended by `at`, then id. A lost race costs a re-ordering, never a preset.
- **At most 64 presets** (a limit in the editor and in validation: a 65th is refused, an existing file with more shows the first 64 by order and keeps the rest). Names, colors and widths are not secret from the vault holder; they are in the settings file's ciphertext.
- Registry: `SharedSettingsCatalog` gains **key families** (a prefix, a value validator, "used by every device"); `SharedSettingsSchema` emits `patternProperties` for `^palette\.tool\.[0-9a-f-]{36}$` and a `palette.toolOrder` array
  schema; `sempere settings validate` knows both. This is additive (settings-sync.md §6.2 rule 1): `$schemaVersion` and `$minReaderVersion` stay 1; `registry-v1.json` snapshot gains the family; an
  older app keeps the keys verbatim (rule 5) and does not show presets. A test pins "an older registry's reader keeps `palette.tool.*` through a save".
- Rows in the settings-sync.md §5.1 table: `palette.tool.<uuid>` and `palette.toolOrder`, "Used by every device", shown under Settings ▸ Writing ▸ Saved Tools rather than as raw rows.
- Never in a type block in 1.3: the UI and the CLI write only the top level, and the reader ignores `palette.tool.*` inside `[mac]`/`[ipad]`/`[iphone]` (kept verbatim, not shown).
  The point is one set on every device; per-type presets are Later.

### 3.3 With sync off, and with overrides (D3)

Saved tools follow the settings-sync model exactly:

- **Sync Settings with This Vault off:** the presets live in a per-device list in `UserDefaults` (`Sempere.savedTools`, the same shape, next to `DrawingToolbox`'s
  `Sempere.drawingTools`), and the palette shows that list.
- **On:** the palette shows the **open vault's** presets (resolution order of settings-sync.md §2.3), applied while that vault is open, like `editor.compactPalette`. Opening another vault shows its presets.
- **Turning sync on** follows §4.2, with the whole family counted as one setting: if the vault has no `palette.tool.*` slot (live or reset), this device's local list seeds them; if it has some, the device shows "use the vault's" (default) or "replace the vault's with this device's".
- **No "Only on This Device" for saved tools in 1.3.** Overrides are per key (settings-sync.md §4.3); a group override over a key family would be new machinery for little gain.
  With sync on, the presets are the vault's; a device that wants its own turns sync off.
- Read-only or untrusted vaults (settings-sync.md §4.5): presets can still be used; saving a new one is paused with the standard message, or saved to the local list when sync is not on.

### 3.4 Selecting and editing

`DrawingToolState` gains the pure logic (Linux-tested), so app and CLI share it:

- `SavedTool` (the value above), `SavedToolList` (ordering, reconciliation, the 64 cap, id and name resolution).
- `apply(_ tool: SavedTool)`: `tool` becomes the preset's ink and that ink's `InkSettings` become the preset's color, width and opacity. The state stays the one tool model: a preset is a shortcut to a state, never a second kind of tool.
- `isActive(_ tool: SavedTool)`: true when the current tool is that ink and its settings equal the preset's exactly (width and opacity with a small tolerance). Adjusting the width afterward deselects the preset, because the state no longer matches; there is no hidden "preset mode".
- `saving(current:name:)`: a new preset from the current tool and settings (refused for the eraser and lasso).

### 3.5 App UI

**iPad and Mac, full palette** (`DrawingPaletteView.fullBar`): after the built-in tools, a **Saved** group: one button per preset, drawn as the ink's icon tinted with the color and a dot of the width
(`PaletteButton`), highlighted when `isActive`. The group scrolls horizontally when it does not fit (`ViewThatFits`'s order: inline, then behind the color button, then the compact bar, as now); a **+** button
("Save Current Tool as Preset…") sits at its end. Tap or click applies; a Pencil tap too. Context menu (long press on iPad, right-click on Mac): **Edit…**, **Duplicate**, **Move Left**, **Move Right**, **Delete** (asks once). Dragging reorders where the platform makes it easy (Mac and iPad pointer); the menu entries are the accessible path.

**Editor sheet** (new, one view for create and edit; a popover on iPad and Mac, a sheet on iPhone): name field, ink picker (the seven inks), color (the eight swatches plus the system color picker, as in the palette),
width (the five presets plus the slider, `widthRange`), opacity (the four presets plus slider), and a **live stroke preview** drawn with the app's renderer. Save and Cancel; Save is disabled for an empty name.

**iPhone and Compact Palette:** the compact bar keeps four tools (`compactTools(selected:)`). A **Saved Tools** button (an icon with a count) opens a popover or half-sheet listing the presets (swatch, name, ink) with an Edit button for
reordering and deletion; picking one applies it and closes. When a preset is active its ink is the selected compact tool and the button shows the preset's color.

**Mac menu:** Tools ▸ **Saved Tools** submenu listing presets with **⌃⌘1** to **⌃⌘9** for the first nine (new `MenuCommand` cases with `[.command, .control]`; `MenuCommandTests`
checks them). Not ⌥⌘digits (the built-in tools, `toolPen` … `toggleHand`, take ⌥⌘1 to ⌥⌘7) and not plain ⌃digits (macOS's "Switch to Desktop N").
"Save Current Tool as Preset…" and "Manage Saved Tools…" (opens Settings ▸ Writing ▸ Saved Tools) are entries too.

**Settings ▸ Writing ▸ Saved Tools:** the list with the same actions and a count. File export and import are CLI-only in 1.3 (§3.6).

**Pencil gestures** are unchanged: "switch to previous" returns to the tool before the preset's, because applying a preset is a tool change like any other. Presets never auto-select by themselves.
Every icon-only button has `.help("…")` and an accessibility label ("Saved tool: Fine red pen, pen, 1.5, red"); all strings are localized with Spanish values.

### 3.6 CLI first

Presets are settings, so the CLI writes the shared file through the same code the settings commands use (`SharedSettings`), with its exit codes (6 untrusted list, 7 read-only or newer `$minReaderVersion`, 3 invalid):

```
sempere tools list   [--json]
sempere tools add    NAME --ink INK --color '#RRGGBB' --width W [--opacity O] [--json]
sempere tools edit   TOOL [--name N] [--ink INK] [--color C] [--width W] [--opacity O] [--json]
sempere tools remove TOOL [--json]
sempere tools move   TOOL (--to N | --before TOOL | --after TOOL) [--json]
sempere tools export [--out FILE] [--json]     JSON: sempere-tools/1, a list of presets without ids
sempere tools import FILE [--replace] [--yes] [--json]   adds new ids; --replace removes the vault's first
```

- `TOOL` is an id, an id prefix or an exact name (an ambiguous name is an error naming the ids).
- `add` validates against the registry (ink, color syntax, width range for that ink, opacity, name length, the 64 cap), `edit` rewrites that slot only, `remove` resets it, `move` writes `palette.toolOrder`.
- `list` shows id, name, ink, color, width, opacity, order; `--json` returns the objects of §3.1 in order.
- The file format `sempere-tools/1`: `{ "format": "sempere-tools/1", "tools": [ { name, ink, color, width, opacity } ] }`. Import assigns fresh ids and skips invalid entries, reporting each. This is the way to share a pen set between vaults and people.
- The CLI has no device-local list (it is not a device that applies settings, settings-sync.md §7): it edits the vault's file. `docs/cli.md`, `settings.schema.json` and settings-sync.md are updated in the same PR.
- Linux works (pure logic).

## 4. Limits

64 presets; name 40 characters; one `palette.toolOrder` array of at most 64 ids; at most 4 KB per preset slot; the per-write settings debounce (about 1 s) applies, so dragging a slider writes once.

## 5. Privacy and security

- Presets are ordinary settings: in `settings.age`, encrypted with the vault's keys, merged by the existing rules; nothing new is visible to a storage provider (it sees the same file change).
- Names are user text shown in the palette: drawn as plain text, never interpreted, bounded to 40 characters; hostile names from a hostile vault holder cannot do more than any setting value. Import and file reads use
  `BoundedRead` and the settings parser's limits; unknown inks and fields are kept, never trusted; invalid slots are skipped with a warning.
- No network, no new entitlements, no new API categories.

## Decisions

- **D1 No format change, no `features` entry.** Presets are new settings keys; older apps keep them verbatim (settings-sync.md §6.2).
- **D2 A preset is a shortcut to a `DrawingToolState`, not a new tool type.** One tool model on every device; the active highlight is computed from equality.
- **D3 Stored in the shared settings, one slot per preset plus an order slot; follows the existing sync-switch, override and seeding rules.** Per-key merge means concurrent additions never lose one.
- **D4 Width out of range is skipped, not clamped.** Every device then agrees on what a preset is.
- **D5 Cap of 64, name of 40 characters.** Bounded file growth and a sane palette.
- **D6 Eraser, lasso and ruler are not presets.**
- **D7 Mac shortcuts ⌃⌘1 to ⌃⌘9.** ⌥⌘digits are the built-in tools; plain ⌃digits are Mission Control's.
- **D8 CLI: `sempere tools`, writing through the settings layer, plus `export` and `import` of a small JSON file.** The way to share a set without a new vault feature.

## Decisions (reviewer, 2026-11-18)

1. **With sync off, per vault or per device?** Per device (`Sempere.savedTools`); with sync on they follow the open vault. Reason: every other palette state is per device; per-vault local lists add a store for nothing.
2. **Dark-mode color in a preset?** No: stored as drawn on light paper. Reason: ink colors are stored that way and the palette's `shown(_:)` already maps them for display.
3. **Eraser size or mode as presets?** No. Reason: the eraser has its own two modes and size rows (`eraser.mode`, `eraser.objectRadius`); a preset is an ink.
4. **Reorder by drag only on pointer devices?** Yes; Move Left and Move Right in the context menu everywhere. Reason: touch drag inside a scrolling palette fights the scroll; the menu is the accessible path.
5. **Where in Settings?** Writing ▸ Saved Tools. Reason: it sits with the palette settings and is small.
6. **Presets in type blocks?** Not in 1.3: top level only, and a preset in a type block is kept but not shown. Reason: one set on every device is the feature; per-type sets need UI we do not have.
7. **Pencil double-tap to cycle presets?** Not in 1.3. Reason: it belongs to the planned `pencil.doubleTap` setting (settings-sync.md), designed with it.
8. **Group override ("Only on This Device")?** Not offered. Reason: overrides are per key; turning sync off already gives a device its own presets.
9. **Key names:** `palette.tool.<uuid>` and `palette.toolOrder`. Reason: one prefix for the family and its order, in the catalog's dotted style.
